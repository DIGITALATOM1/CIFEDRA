# Базы сценарий-результат WORK / LIFE

Дата: 2026-11-15. Версия схемы: 0.2. Только подготовка; не production dataset.

- [work.json](./work.json): 20 L1, 103 L2; две ветки инициаторов и 12 семейств запросов, включая исследовательский блок.
- [life.json](./life.json): 20 L1, 106 L2; шесть исследованных оснований и пять жизненных контекстов.
- [Исследования и метод v0.2](../../research/cifedra-life-needs-work-demand-foundation-2026-11-15.md).
- [Обзоры двух графов](../cifedra-work-life-goal-graphs-2026-11-15.md).
- Mermaid-источники: [WORK](./work-overview.mmd), [LIFE](./life-overview.mmd).

Паспорта Markdown — вход подготовки; JSON — производная модель для будущей
визуализации. При изменении паспортов требуется синхронизация. Версия шаблона
не равна версии экземпляра и не означает выполненную работу.

## Узлы

`life_orientation` — общий персонализируемый ориентир; `domain` — WORK/LIFE;
`human_need` — исследованный конструкт в продуктовом синтезе;
`life_context` — область повседневного применения, не базовая потребность;
`demand_stream` — человек/бизнес; `request_family` — семейство запросов с типом
источника; `scenario_result` — сценарий с результатом. Прежний тип `need` из v0.1
заменен; сценарии и их ID сохранены. foundation.sources хранит источники,
coverageGaps — явно непокрытые темы.
Один тип для L1 и L2 сохраняет рекурсивность декомпозиции. Уровень задается явно.
Номер ID стабилен в текущем комплекте и не является рейтингом популярности.

ID GOAL-BALANCE одинаков в двух независимых проекциях; это один концептуальный
ориентир, а не два результата и не технический мост объединения библиотек.

## Ребра

| Тип | Семантика |
| --- | --- |
| framing | Ориентир задает рамку направления, не критерий завершения |
| need_foundation | LIFE организован вокруг исследованных потребностей |
| candidate_application_context | Возможная область применения; продуктовая гипотеза |
| candidate_scenario_for_context | Сценарий-кандидат внутри контекста |
| demand_segmentation | Ветка запросов человека или бизнеса |
| request_group | Семейство запросов внутри ветки |
| candidate_scenario_for_request | Кандидат сценария достижения результата по запросу |
| decomposes_to | Частный результат входит в подтвержденный scope родителя |
| supports | Условно может дать часть входа/результата другого сценария |
| optional_support | Необязательная дополнительная поддержка |
| candidate_reuse | Кандидат на переиспользование шаблона после review критериев |

Ребра supports/optional_support/candidate_reuse — proposed, с условиями;
causalityProven=false и autoCreateAlliance=false. Транзитивные гарантии не выводятся.
Декомпозиция не задает временную последовательность. Повторяющийся смысл пока
не объединен в один canonical template автоматически.

L2 acceptanceCriteria=null означает незавершенную детальную проработку, не
отсутствие необходимости приемки. Глобальный ориентир и потребности не требуют
выполнения всех 20 сценариев. Личные ограничения balance.targets пока не заданы;
единицы/период/значения заполняются только в реальном пользовательском контексте.
executionInstances и alliances пусты: людей и их согласий в подготовительной базе нет.

Проверка: `node scripts/quality/check-scenario-bases.mjs` из корня проекта.
