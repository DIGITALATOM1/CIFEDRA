# SRS Knowledge Base

Раздел хранит утверждаемые требования к поведению CIFEDRA:

- scope and actors;
- functional and non-functional requirements;
- invariants and lifecycle;
- authorization;
- acceptance criteria;
- traceability to CJM, architecture, code and tests;
- review history.

SRS не должен зависеть от конкретного UI или внешнего продукта, если это не
является явным требованием.

## Planned SRS sequence

Актуальная последовательность определена в
[Project Improvement Roadmap](../delivery/cifedra-project-improvement-roadmap-2026-07-26.md):

1. product/technical terminology and lifecycle mapping;
2. Request Bundle and Work Card;
3. AI Matching, No Exact Match and Rematching;
4. Alliance Board and role actions;
5. Agreement, pricing and change approval;
6. Recurring Work;
7. Result, Verified Help and Reference;
8. catalog, capabilities, tags and filters;
9. messenger and disclosure;
10. payment reservation/refund contract;
11. country configuration and localization.

`WORK`, `LIFE`, `SKILLS` используют общий Core SRS и direction-specific
deltas. Полные копии одного SRS по направлениям не создаются.
